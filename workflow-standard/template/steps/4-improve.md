# 阶段④ 改善 / 学习 (Improve)

**目标**：依据评分证据，对策略做一次**小步、有据、可回滚**的修订。这是闭环的灵魂，也最易过拟合。

## 步骤
1. 读取近若干轮 `state/scorecard.jsonl`，找出一致性的失败模式（非单日噪声）。
2. 提出**一处**小改动（一条规则或一个阈值），并写下假设：
   "预期此改动改善哪个指标"。
3. 修改 `state/strategy.md` 对应条款。
4. 在 `strategy.md` 文末"变更日志"表追加一行：
   `日期 | 改了什么 | 理由(引用哪些 scorecard 证据) | 预期改善的指标 | 回滚方式`
5. （若已 git init）本次改善单独提交，获得可回滚的改善史。

## 产出
- `state/strategy.md` 更新 + 变更日志追加。

## 硬约束（STANDARD.md §8）
- 有据可依：必须引用具体 scorecard 证据。
- 小步：单轮最多改一处，禁止整篇重写。
- 可回滚：保留旧版本，能一键回退。
- 防过拟合：不得针对单日噪声调参，证据需跨多日/多样本一致。
- 下一轮③评估据"假设"验证本次改动是否真的有效。
