# 多 Bot 定期协作计划

> 这是什么：OneWonder 多 Bot 定期协作的运营计划（路径、格式、节奏、闭环与拍板项）。  
> 状态：草案 · 2026-09-11 调研后起草 · **未合并** · 政策/归属变更一律进「需要拍板」。  
> 落点：`ow-open-knowledge`（公开知识仓）`docs/` 下的运营计划稿；不改应用代码。

---

## 1. 背景与目标

### 1.1 背景

组织内已有多条并行轨（公开知识蒸馏、知识中枢门户、每日情报、宠物内容、首页/FDE、算力与工作流基建等），以及多名专职 Bot。若缺少统一的「调查→整理→分析→入库/隔离→审计」闭环，会出现：

- 调查记录格式不一，无法复盘；
- 整理产物散落，公开仓与内部仓边界模糊；
- 社交外发与外部习得混入既有知识库；
- 未验证外部知识直接入库；
- 仓库/路径孤儿文件无人认领。

机主已给出五条共通规则（调查 / 整理 / 社交 / 分析 / 管理）。本计划**保留原文精神**，将其落实为可执行的格式、路径与节奏；缺环以「需要拍板」列出，不静默改写规则。

### 1.2 目标

1. 各 Bot 知道自己**写什么格式、写到哪、多久一次、交给谁审**。
2. 五条共通规则成为可检查的运营动作（有样例路径与门禁）。
3. 闭环缺口显式化：脱敏、晋升门、机主批准、排程归属。
4. 与既有仓约定**对齐而非复制**：`ow-open-knowledge` 主题目录、`owd-daily-intel` 日更、`owd-knowledge-hub` 结构/内容分离、`ai-ops` 仓库总账与规则正本。

### 1.3 成功判据（本文件）

- [x] 文件落在指定分支；
- [ ] 五条规则已操作化（格式 + 路径 + 节奏）；
- [ ] 闭环缺口已点名；
- [ ] 「需要拍板」非空（有不明项即列）；
- [ ] 不 merge、不删文件、不改应用代码。

## 4. 共通规则（操作化）

> 以下五条为机主规则原文精神；括号内为落地约定。**改政策/归属 → 需要拍板，不在此静默改写。**

### 4.1 调查类：统一调查记录格式

**规则**：调查类产出使用统一调查记录格式。

**格式（建议文件名）**：`YYYY-MM-DD-<短slug>.md`

```markdown
# 调查记录 · YYYY-MM-DD · <标题>

- 记录 ID：INV-YYYYMMDD-<序号>
- Bot：<名称>
- 类：调查
- 来源：<会议 / 仓库 / 社区公开信息 / 其他>（附可核对引用）
- 关联轨/仓库：<可选>
- 机密分级：L1 / L2 / L3（对齐 open-knowledge `agent-cultivation/data-classification.md`）
- 状态：草稿 | 待验证 | 可整理 | 已关闭

## 事实（仅可核对）
- …

## 观察 / 假设（显式标注未核实）
- …

## 行动项
| ID | 内容 | Owner | 截止 | 状态 |
|---|---|---|---|---|

## 下游
- 是否需要整理：是/否 → 目标 path
- 是否需要分析门：是/否
- 是否涉及对外：是/否 → 仅经社交 Bot + 脱敏
```

**节奏**：产生调查的当日完成记录；行动项未关闭则进入秘书日向。

**路径**：默认调查区（拍板 #2）；日更摘要可同步一条到 `owd-daily-intel`（私有、非永久）。

### 4.2 整理类：指定 path + 统一格式，供日后公开 KB 摄入

**规则**：整理类写到指定路径，并用统一格式，便于后续公开知识库摄入。

**格式（建议）**：

```markdown
# <主题>

> 这是什么：<一句话>
> 来源调查：INV-… / 无
> 分级：L1（公开候选）| L2（社内）| L3（禁止公开）
> 摄入状态：草稿 | 待脱敏 | 待晋升 | 已摄入

## 可复用结论
## 步骤 / 清单（可核对）
## 反例 / 踩坑
## 公开摄入映射（可选）
- 目标仓：ow-open-knowledge
- 目标目录：agent-cultivation | workflow-standard | cloud-patterns | team-norms | …
- 建议文件名：
```

**路径约定（与现仓对齐）**：

| 内容类型 | 建议落点 |
|---|---|
| Agent / 育成 / 数据分级 | `ow-open-knowledge/agent-cultivation/`（晋升后） |
| 工作流闭环方法 | `ow-open-knowledge/workflow-standard/` |
| 团队协作规范 | `ow-open-knowledge/team-norms/` |
| 尚未晋升的整理稿 | 内部暂存区（拍板 #2），**禁止**直接推 `owd-knowledge-hub` 冒充内容更新 |
| 门户设计稿 | 仅 `owd-knowledge-hub/design/YYYYMMDD-主题-vN`（设计负责人流程） |

**节奏**：内容向 Bot 按 §3 周历沉淀；晋升公开仓须过 §4.4 + 机主/指定审批（拍板 #4）。

### 4.3 社交类：唯一外发 Bot；仅脱敏知识；外部习得与既有 KB 隔离

**规则**：只有社交 Bot 对外部社区说话；只外发脱敏知识；外部交换学到的东西**单独存放**，不得写入既有知识库。

**操作化**：

1. **发言权**：仅 **neng社交的** 可对外发帖/回复；其他 Bot 最多把「建议外发草稿」放进队列。
2. **外发内容**：须完成脱敏（客户实名/个资/密钥/未发表 IP 等按 L3 处理）；对照 `data-classification.md`。
3. **隔离区（建议路径，拍板 #3）**：
   - `external-exchange/raw/YYYY-MM-DD-*.md` — 外部原文摘要（仍脱敏）
   - `external-exchange/learned/YYYY-MM-DD-*.md` — 习得条目（默认「待验证」）
   - **禁止**写入：`ow-open-knowledge` 主题目录、W2 知识库正本、`ai-knowledge-local` 活跃已验证集、CDN `kb-data.json` 生产线。
4. **与 daily-intel 关系**：面向制作群的「今日份」可继续用 `owd-daily-intel`；其中标「社区帖 / 非永久」的条目**不等于**已入库。

**节奏**：外发窗口工作日 11:00 / 16:00；隔离区写入每日 20:00。

### 4.4 分析类：未验证/外部知识经高强度分析；拆成「可入库」与「待验证」

**规则**：未验证或外部知识，使用 grok-4.6、effort **xhigh** 做分析；结果拆成 **可入库** vs **待验证**。

**操作化**：

1. **触发**：来自社交隔离区、外部公开信息、未经内部复现的技巧/结论、调查记录中的「假设」。
2. **分析输出格式**：

```markdown
# 分析 · YYYY-MM-DD · <标题>

- 分析 ID：AN-YYYYMMDD-<序号>
- 模型约定：grok-4.6 / effort xhigh
- 输入来源：<隔离区 path / INV-…>
- 机密分级：…

## 可入库（Promotable）
| 条目 | 依据 | 建议目标 path | 仍需的人工确认 |
|---|---|---|---|

## 待验证（Pending）
| 条目 | 缺什么证据 | 建议复现实验 | Owner |
|---|---|---|---|

## 明确丢弃 / 不入库
- …（写理由）
```

3. **门禁**：标「可入库」仍须 **晋升门**（脱敏复查 + 指定审批，拍板 #4）后才能进入公开/正本 KB。  
4. **节奏**：工作日 17:00–18:00 批处理当日队列；重大外部争议可即时加塞。

### 4.5 管理类：定期审计仓库与路径；杜绝孤儿文件

**规则**：定期审计各仓库与路径，不留无人认领的孤儿文件。

**操作化（管仓库的主责，秘书抽查）**：

1. **日检**：对照 `ai-ops/repos.md`——有无远端、未推送提交、救援分支是否超期。
2. **周检（周日）**：  
   - 无 README / 无 Owner 标注的新建路径；  
   - `investigations/` `external-exchange/` `audits/` 暂存区超过 N 天未关闭（N 默认 14，拍板 #5）；  
   - 公开仓是否混入 L3；  
   - `owd-knowledge-hub` 是否被误当作内容仓写入。
3. **审计报告格式**：`audits/YYYY-MM-DD-repo-orphan.md`，含：孤儿清单、建议归档/认领/删除（**删除必须机主确认**，对齐 AI_RULES）。
4. **节奏**：日 10:00 + 周日 11:00。

## 5. 闭环检查

目标闭环：

```text
调查 → 整理 →（若外部/未验证）分析门 → 脱敏 → 晋升门/机主批准 → 入库或隔离 → 管理审计
                ↑________________ 社交外发仅走脱敏队列；习得回隔离区 ________↑
```

### 5.1 已覆盖

| 环节 | 覆盖方式 |
|---|---|
| 调查格式 | §4.1 |
| 整理 path + 格式 | §4.2 |
| 社交唯一出口 + 隔离 | §4.3 |
| 分析分流 | §4.4 |
