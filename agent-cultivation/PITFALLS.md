# 踩坑清单（実装knowhow — これ自体が商品）

> 参考実装を作る過程で実際に踏んだ坑を全て記録する。顧客案件の見積り精度と信頼の源泉。

## 2026-07-03 薄切片構築時

1. **マスキングの再帰マッチ**: 「佐藤健一様→担当者甲様」置換後、人名パターンが「担当者甲様」を
   再度人名と誤認して二重置換。→ 置換済みラベルをスキップする防護を必ず入れる。
   教訓: 脱敏は「置換順序と再入」のバグが出やすい。テストケース必須。
2. **構造検査の見出し誤検知**: 文書タイトル(h1)直後に章見出しが来る正常パターンを「空の章」と
   誤報。→ h2以下のみを対象に。
3. **Windows コンソールの文字化け**: UTF-8出力が cp932 コンソールで化ける(動作には無害)。
   デモ時は必ずファイル出力側を見せる or `chcp 65001`。
4. **CJKユーザー名問題(画像生産PJ側から継承した知見)**: HuggingFace/sentencepiece系は
   `C:\Users\<user>\` 配下のキャッシュを読めない → `HF_HOME=C:\hf_cache`。
   .ps1 に日本語を書くなら UTF-8 BOM 必須。
5. **APIキーが無い段階のデモ**: Claude Code の `-p` モード(サブスク認証)で本物のLLM出力を
   デモできる。ただし PoC 限定・本番は API 契約(規約と商用条件の確認を先に)。

## 2026-07-03 実データ(PPTX提案資料)投入時

6. **PPTXの本文はshape単位で散らばる**: テキストフレーム/表/グループ/ノートを全部歩く必要がある。
   → tools/pptx_extract.py。スライド順は保たれるがレイアウト上の読み順とは限らない点に注意。
7. **実文書の人名は敬称なしが普通**(体制図の自社側)。「X様」パターンだけでは半分漏れる。
   → 実名辞書(entities.local.json, gitignore)方式が本命。NER(GiNZA)導入までは辞書整備が必須工程。
8. **人名ラベルの容量**: 甲乙丙丁…の8個では実文書(36名)で即座に衝突。連番(担当者01..)に変更。
9. **同一実体の表記ゆれ**(「株式会社◯◯」「◯◯製作所」「◯◯」の混在、姓のみ表記): custom直接指定で
   同一ラベルに寄せる。会社名を自動連番にすると表記ゆれで別会社に見えてしまう。
10. **拠点名・製品名も機密**(データセンタ所在地、サービス名)。人/会社の2種別では足りない
    → custom {実語:伏せ字} を追加。
11. **姓名間の空白が全角/半角混在**している実文書がある。辞書には「見たままの表記」を登録し、
    リークチェック(断片検索)で漏れを検出して辞書に追補するループが実用的。
