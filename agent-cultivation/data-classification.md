# 禁传数据清单・机密分级规则 v0.9（初稿・待经营者批准后W1发布）

> 2026-07-05 起草。依据: ai-stack「AI研究会资料」§4 机密三段阶 + 团队90天起步计划 W1 验收标准「明确禁传数据清单」。
> 适用: 全员・全AI工具（Claude/Codex/Gemini/其他云服务）。发布后全员签收，违反=P0安全事件。

## 1. 机密三段阶（数据分级）

| 段阶 | 定义 | 允许的处理 |
|---|---|---|
| L1 公开 | 已公开/可公开信息 | 任何已审批工具直接使用 |
| L2 社内 | 未公开但非客户机密（内部计划/一般业务文书） | 已审批工具可用，**开启商业条款数据保护**的账号才行 |
| L3 机密 | 客户实名/个资/客户机密文书/密钥 | **禁止直接投入任何云端AI工具**。必须先脱敏（伏字化），或全程本地处理 |

## 2. 禁传数据清单（L3——以下内容禁止原文投入云端AI）

1. **客户企业的实名信息**: 公司名/人名/拠点名/产品名/案件名（→ 走 ai-stack 脱敏管线伏字化后才可送云）
2. **客户交付物与受领资料原文**（提案书/设计书/PPTX等）
3. **个人信息**: 社员与客户的姓名+联络方式/住所/评价信息
4. **认证凭据**: API key/密码/token/证书（→ 只放Secrets管理器；出现在代码或prompt里=事故）
5. **未公开财务/合同/报价信息**
6. **未发表IP设定原案**（各创作项目的角色设定/世界观资料——防泄漏也防训练数据混入）
7. **受限内容素材**（专用管线之外的任何工具禁止，平台条款风险）

## 3. 执行规则

- 判断不了属于哪级 → **按更高一级处理**，并问Team Lead
- L3需要AI处理时: 先脱敏（实名→伏字，对应表只存本地`entities.local.json`方式）→ 云端处理 → 本地逆映射还原
- 双向检查: 送信前查一次，产出物回来再查一次（ai-stack 泄漏检查已代码化）
- 每周工具治理检查时抽查各工具的会话记录合规性
