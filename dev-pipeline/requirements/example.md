# 要件: ヘルスチェックエンドポイントの追加

既存の Web アプリに監視用のヘルスチェックを追加する。

## 背景

外部監視サービスから死活監視したいが、現状トップページを叩いており、
DB 障害時にもトップページが 200 を返すため障害を検知できない。

## 実現したいこと

1. `GET /healthz` を追加し、以下を検査した結果を JSON で返す
   - アプリ自身が応答できること
   - DB へのクエリが成功すること
2. すべて正常なら 200、いずれか失敗なら 503 を返す
3. レスポンスに機密情報（接続文字列・スタックトレース）を含めない
4. 認証不要でアクセスできること（監視サービスから叩くため）

## 制約

- 既存のルーティング構成とエラーハンドリングの書き方に合わせる
- ヘルスチェック自体が重いクエリにならないこと（`SELECT 1` 相当で十分）
- 単体テストを付けること（正常系・DB 障害時の 503）

## 完了条件

- `GET /healthz` が正常時に 200、DB 停止時に 503 を返す
- テストが通る
