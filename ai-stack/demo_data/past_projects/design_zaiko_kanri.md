# 基本設計書：在庫管理システム再構築（B社）

## 1. 概要
B社の在庫管理業務をExcel運用からWebシステムへ移行する。拠点3箇所の在庫をリアルタイムに一元把握し、棚卸工数を50%削減する。

## 2. システム構成
- Webアプリ（社内LAN + VPN経由リモート）
- アプリ層: Python/FastAPI、フロント: React
- DB: PostgreSQL 15（オンプレ、日次バックアップ）

## 3. 機能一覧
| # | 機能 | 概要 |
|---|---|---|
| F1 | 入出庫登録 | バーコードスキャンで数量登録 |
| F2 | 在庫照会 | 拠点横断の在庫検索・閲覧 |
| F3 | 棚卸 | 棚卸リスト出力と差異登録 |
| F4 | 発注点アラート | 安全在庫を下回った品目を通知 |
| F5 | 帳票出力 | 月次在庫報告(Excel/PDF) |

## 4. 画面設計
ログイン / ダッシュボード / 在庫一覧(検索・絞込) / 入出庫登録 / 棚卸 / 管理者設定 の6画面。
一覧系は共通グリッドコンポーネントを使用し、列定義のみ差し替える。

## 5. データ設計
主要テーブル: items(品目) / stocks(拠点別在庫) / transactions(入出庫履歴) / users / audit_log。
transactionsは月次パーティション。論理削除は用いず、取消は逆仕訳で表現する。

## 6. 外部連携
- 基幹会計システムへ日次CSV連携（SFTP、23:00バッチ）
- バーコードリーダー(HID接続)

## 7. 非機能要件
- 同時接続50ユーザー、画面応答2秒以内
- 稼働率99.5%（計画停止除く）、RPO=24h/RTO=4h
- 権限: 一般/拠点管理者/本社管理者の3ロール

## 8. 移行・運用
Excel台帳からの初期データ移行はツールで一括変換し、2週間の並行運用後に切替。運用手順書と障害時連絡フローを納品物に含む。
