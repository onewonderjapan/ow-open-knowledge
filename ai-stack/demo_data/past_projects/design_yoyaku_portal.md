# 基本設計書：会員向け予約ポータル構築（C社）

## 1. 概要
C社の施設予約業務（電話受付）をWeb予約ポータル化する。会員が空き状況を確認し予約・決済まで完結できるようにし、受付業務を70%削減する。

## 2. システム構成
- パブリッククラウド(AWS)上のWebアプリ。CloudFront + ALB + ECS(Fargate)
- アプリ層: TypeScript/NestJS、フロント: Next.js
- DB: Aurora PostgreSQL。決済は外部決済代行(トークン方式、カード情報は非保持)

## 3. 機能一覧
| # | 機能 | 概要 |
|---|---|---|
| F1 | 会員登録・認証 | メール認証、パスワードリセット |
| F2 | 空き照会 | カレンダー形式の空き状況表示 |
| F3 | 予約・変更・取消 | 会員自身で完結。取消規定に応じ自動計算 |
| F4 | オンライン決済 | クレジット/コンビニ払い |
| F5 | 管理者機能 | 枠管理、会員管理、売上集計 |
| F6 | 通知 | 予約確認/前日リマインドのメール送信 |

## 4. 画面設計
会員側8画面（トップ/空きカレンダー/予約フォーム/確認/マイページ等）+ 管理側5画面。
スマートフォン優先のレスポンシブ。管理側はPC前提。

## 5. データ設計
members / facilities / slots(予約枠) / reservations / payments / notifications。
reservationsはステータス機械(仮予約→確定→取消)で遷移管理し、payments と1:1。

## 6. 外部連携
- 決済代行API（Webhookで入金確定を受信）
- メール配信SaaS（送信ログを自システムに保存）

## 7. 非機能要件
- ピーク時 200 req/min（受付開始直後）、オートスケール対応
- 個人情報は暗号化保存(KMS)、アクセスログ1年保管
- 稼働率99.9%、多要素認証は管理者のみ必須

## 8. 移行・運用
既存会員名簿(Excel)をクレンジングして移行。電話予約は3ヶ月間併存させ、段階的にWeb誘導。月次で利用状況レポートを提供。
